# Writer Agent — Preflight 详细预检清单

> 在 `writer.md` 流程三中引用。执行预检时必须逐项核对本清单。

---

## 预检执行总则

1. **逐项检查**：六大维度全部检查完毕后才能给出判定
2. **发现阻断项立即记录**：记录问题位置（章节/段落）、问题类型、严重程度
3. **禁止跳过**：任何一条未检查都不得进入 Commit
4. **基于证据判断**：所有判断必须有 canon 证据支持，不能凭感觉

---

## 一、文风一致性检查

### 1.1 视角检查
- [ ] 全文是否严格维持**第三人称有限视角**？
- [ ] 是否始终紧贴**林渡尘的感知与内心**？
- [ ] **禁止**：跳转到其他人物内心独白（角色行为和对话可以展示他人情绪，但不可直接写"他想/他觉得"）
- [ ] 检查方法：搜索 `他想`、`她觉得`、`心里` 等词汇，确认没有非渡尘角色的内心描写

### 1.2 时态一致性
- [ ] 主叙事是否以**现在时**为主？
- [ ] 回顾/追忆段落是否明确切换为**过去时**？
- [ ] 时态切换是否有明确的过渡标记（如"那时候"、"三年前"等时间锚点）？

### 1.3 节奏检查
- [ ] 沉浸段（环境描写、角色独白、细节铺陈）：节奏是否偏慢？是否有五感铺陈？
- [ ] 推进段（对话交锋、行动决策、冲突展开）：节奏是否紧凑？镜头切换是否得当？
- [ ] 是否存在节奏失当（沉浸段过于匆忙 / 推进段过于拖沓）？

### 1.4 词汇检查（搜检以下禁用类型）
- [ ] **滥用成语**：连续使用两个以上四字成语 → **必须修改**
  - 示例违禁：「他战战兢兢、诚惶诚恐地走进去」（两个四字熟语串）
- [ ] **浮夸形容词**：`致命的`、`震撼的`、`恐怖的`、`惊为天人的` → **必须修改**
  - 替代方案：用具体感官描写替代抽象形容词
- [ ] **现代口语**：`好吧`、`其实`、`大概`、`反正`、`怎么说呢` → **必须修改**
  - 例外：如果角色设定本身就是市井出身，允许有限的现代口语，但需在角色档案中标注
- [ ] **感叹号滥用**：一个自然段内出现超过一个感叹号 → **检测并标记**

### 1.5 句式检查
- [ ] 全文是否以**短句为主**？
- [ ] 段落收束处是否使用**短句或寓言式断语**？
- [ ] 长句是否仅用于感官铺陈（且不过度堆叠）？

### 1.6 整体流畅度
- [ ] 通篇读起来是否流畅自然？
- [ ] 是否有明显的文风断裂（前面紧贴感官，后面突然变成说明文）？
- [ ] 寓言体句式是否恰当地用于关键转折点收束，而非随意使用？

---

## 二、大纲一致性检查

### 2.1 目标达成检查
- [ ] 对比 `outline/chapters/<chapter_id>.md` 中定义的 `goals`（3-5 条）
- [ ] **是否每条 goal 都在本章正文中体现？**
- [ ] **未达成的 goal**：记录哪条 goal 未体现，判断是否需要调整计划或补充草稿

### 2.2 越级推进检查
- [ ] 是否提前推进了属于后续章节的目标？
  - 对比 `outline/chapters/` 中后续章节（ch-XXX 且 index > 当前）的 `goals`
  - 如果本章内容包含了后续章节的目标 → **BLOCKED**（除非用户显式批准章节重排）
- [ ] 是否提前揭示了属于后续章节的设定/信息？
  - 例：在 ch-006 不能揭示应在 ch-010 才出现的禁忌之地真相

### 2.3 依赖检查
- [ ] 当前章节 `dependency` 中列出的所有前置章节是否均为 `finalized`？
- [ ] 本章使用的信息/设定是否都能在已 finalized 的章节中找到来源？
- [ ] 是否存在引用未入典草稿内容的情况？ → **BLOCKED**

### 2.4 场景卡覆盖
- [ ] 本章所有场景卡（`scene_cards/sc-ch<NNN>-*.md`）的 `goal` 是否在正文中达成？
- [ ] 每个场景是否有明确的 `outcome`（结果）？
- [ ] `conflict`（冲突）是否被呈现而非绕过？

---

## 三、角色一致性检查

### 3.1 出场角色清单
- [ ] 列出本章所有出场角色
- [ ] 对于 `key_characters`，确认每个角色都被充分推进（不只是一笔提及）

### 3.2 角色性格一致性
- [ ] 逐角色对比 `characters/<角色>.md` 中定义的核心特质
- [ ] **检查项**：
  - 性格有无无依据突变？（例：温和的人突然暴怒，但无铺垫）
  - 决策是否符合角色动机？（例：渡尘不会因为压力放弃追查数据异常）
  - 说话风格是否与角色设定一致？（例：章典说话必定刻板正式，不会使用比喻）
  - 情感反应是否与角色心理状态匹配？

### 3.3 角色能力一致性
- [ ] 角色在本章展现的能力是否在已有档案范围内？
- [ ] 新能力是否在 Preflight 中合理解释（来源、触发条件、代价）？
- [ ] 是否存在能力降级（之前描写角色能做某件事，本章突然做不到但无解释）？

### 3.4 角色关系一致性
- [ ] 对比 `relationships/` 中的关系记录
- [ ] 角色互动是否与已有关系强度/状态一致？
- [ ] 关系变化是否有充分的剧情铺垫？
- [ ] **关系反转**（从敌对到合作、从信任到背叛）→ 是否有伏笔支持？
  - 无伏笔的关系反转 → **BLOCKED**

### 3.5 角色年龄/外貌一致性
- [ ] 角色的年龄是否与 `overview.md` 一致？
- [ ] 外貌特征描写是否与角色档案一致（如有记录）？
- [ ] 时间流逝（跨章节）是否体现在角色状态上？

---

## 四、世界一致性检查

### 4.1 硬规则检查
- [ ] 对照 `world/` 中定义的所有 **硬规则**（标记为不可违反的规则）
- [ ] **物理规则**：
  - 微界是直径 127m 的球体 → 不能出现超过这个尺度的场景
  - 双光源 12 小时交替 → 不能出现"正午的太阳"之类的描述
  - 光源升降方向固定（先冷白后暖金） → 描述不能颠倒
  - 重力裂隙的表现形式（失重、加重、偏转）→ 不能出现世界设定中没有的裂隙类型
- [ ] **社会规则**：
  - 教会五层架构（四司 + 衡光卫）→ 不能出现不存在的部门
  - 圣者权力范围 → 不能出现超越设定的权力描述
  - 仪式规则（轨还祭、裂隙礼等）→ 描述必须与 `rituals.md` 一致

### 4.2 地点一致性
- [ ] 新地点是否在 `world/overview.md` 中有记录或准备记录？
- [ ] 已有地点的描写是否与 `world/` 中的描述一致？
  - 例：仰穹台在神殿域顶层 → 不能写"从仰穹台向下看到居住层的灯火"（视角/空间关系要正确）
- [ ] 神殿域垂直结构（7 层）是否被正确使用？

### 4.3 势力与政治一致性
- [ ] 角色之间的权力关系是否与教会层级一致？
- [ ] 部门职能是否准确（轨仪司=记录光轨、典藏司=圣典与档案、戒律司=教规与惩戒、祭祀司=仪式与庆典）？

### 4.4 圣典与信仰体系
- [ ] 引用的圣典内容、仪式名称、祷文是否与 `scripture.md` 和 `cosmology.md` 一致？
- [ ] 角色对信仰的态度是否符合其档案设定？
  - 例：严霜是狂热信徒 → 不会质疑圣典内容；渡尘用数据思维 → 会把圣典描述与观测做对比

### 4.5 新设定冲突检测
- [ ] 本章引入的新设定（地点/规则/仪式/历史）是否与已有设定冲突？
- [ ] 新设定是否在候选事实中记录，准备 Commit 时写入 `world/`？

---

## 五、时间线一致性检查

### 5.1 事件顺序检查
- [ ] 本章事件是否发生在已记录事件的**合理时间之后**？
- [ ] 对比 `timeline/world_history.md`，确认本章事件的时间点不与已有事件冲突
- [ ] 多个事件之间的时间间隔是否合理？（事件 A 发生后需要合理的时间流逝才能发生事件 B）

### 5.2 因果链检查
- [ ] 本章事件的**原因**是否在之前的章节中有铺垫？
- [ ] 本章事件的**结果**是否与之前的设定一致？
- [ ] 是否存在因果倒置？（结果出现在原因之前）→ **BLOCKED**

### 5.3 日期/时节一致性
- [ ] 本章的时间标记（圣历年、季节、日期）是否与前章连续？
- [ ] 如果有时序跳跃，是否在文本中有明确的时间过渡？

### 5.4 跨章节时间流逝
- [ ] ch-001 到 ch-005 的事件是否在合理的时序内发生？
- [ ] 角色在时间流逝中的成长/变化是否符合自然规律？

---

## 六、线程一致性检查

### 6.1 必需线程检查
- [ ] 列出 `outline/chapters/<chapter_id>.md` 中 `required_threads` 的所有线程
- [ ] 逐一检查每条线程是否在本章中被**推进**（引入新线索、加深悬念）或**回收**（揭示真相、完成闭环）
- [ ] 未推进也未回收的必需线程 → **BLOCKED**（除非有明确理由标记为推迟）

### 6.2 线程推进质量
- [ ] 推进是否有实质性内容（不只是"提了一句"）？
- [ ] 新线索是否与已有线程内容一致（不矛盾）？
- [ ] 推进的线索是否为后续回收做了铺垫？

### 6.3 新线程标记
- [ ] 本章是否引入了新的伏笔/悬念/谜团？
- [ ] 新线程是否在候选事实中记录（`thread_id`、`introduced_in`、`owner`、`expected_payoff_by`）？
- [ ] 新线程的预期回收点是否在 outline 中合理（不能是在本书范围内无法回收的）？

### 6.4 线程回收判断
- [ ] 标记为回收的线程：回收是否**充分**？读者是否获得了足够的解答？
- [ ] 回收方式是否**有机**（通过剧情自然揭示，而非角色突然开始解释）？
- [ ] 提前回收的线程：回收时机是否过早？是否影响后续章节的张力？

### 6.5 线程不遗漏检查
- [ ] 扫描 `threads/` 中所有 `status: open` 的线程
- [ ] 对于 `expected_payoff_by` 接近当前章节的线程 → 检查是否应该在本章推进
- [ ] 确认没有遗忘任何 open thread（即使不是本章 `required_threads`）

---

## 判定生成

执行完六大维度检查后，汇总所有问题并给出判定：

### 问题分级
- **硬阻断（Hard Block）**：角色/ooc、世界观硬规则违反、时间线因果断裂、必需线程遗漏 → **BLOCKED**
- **软阻断（Soft Block）**：文风偏离、节奏失当、场景目标未完全达成 → **BLOCKED**（需修复但修复成本低）
- **警告（Warning）**：非必需的线程未推进、新设定未标注、细节偏离但可接受 → 记录但不阻断

### 判定规则
- 存在任意 **硬阻断** → `BLOCKED`
- 存在 **软阻断** 但无硬阻断 → `BLOCKED`
- 仅存在 **警告** → `PASS`
- 需要修订 canon 但用户批准 → `PASS_WITH_RETCON`
